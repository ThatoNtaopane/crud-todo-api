Migrate our existing FastAPI task CRUD API from an in-memory list to SQLite with strict production engineering standards:

1. Architecture & Connection Management:
   - Database file: tasks.db in root.
   - Use a helper function get_db() returning sqlite3.connect(..., check_same_thread=False) with conn.row_factory = sqlite3.Row.
   - Use Python context managers (with get_db() as conn:) for all database queries and automated transaction management.
2. Schema & Performance:
   - Table: tasks (id INTEGER PRIMARY KEY AUTOINCREMENT, title TEXT NOT NULL, done INTEGER NOT NULL DEFAULT 0, created_at TEXT DEFAULT (datetime('now')), updated_at TEXT DEFAULT (datetime('now'))).
   - Create indexes on tasks(done) and tasks(title) for optimized query performance.
3. Idempotent Initialization:
   - Initialize schema on FastAPI startup event.
   - Check if table is empty before seeding the 3 initial tasks inside an atomic transaction.
4. Error Handling & Contract Preservation:
   - Preserve custom error response schema: return JSON {"error": "..."} on all 400 Bad Request and 404 Not Found responses.
   - Implement custom RequestValidationError handler returning 400 with {"error": ...}.
   - Return 204 No Content with an empty body on successful deletion.
5. Parameterized Queries:
   - All SQL statements must strictly use ? placeholders.
